# 测试结果

测试日期：2026-11-04。

测试环境：
- Linux，Node.js v22.23.4，Playwright 1.63.0 + Chromium（无头模式）。
- 网页通过 `file://` 打开，和双击 `index.html` 一样。
- Scratch 引擎测试使用 scratch-vm 5.0.300 + scratch-render 2.2.84，在无头 Chromium 里用 SwiftShader WebGL 渲染。

### 课程一致性（`tests/content.test.js`，22 项）

- **结构完整**：12 个项目都有学习目标、前置知识、准备卡（角色、变量和作用域、消息、背景）、绿旗重置说明、2–3 步、每步三级提示、运行检查、常见问题、挑战、反思和家长引导。
- **提示逐级展开**：提示 1 一定是提问；提示 1、2 不出现积木顺序；提示 3 才给出积木顺序或步骤清单。
- **积木真实**：每一行积木都能翻译成 Scratch 3 的真实指令代码。用的就是引擎测试的那个翻译器。
- **中英文对应**：中文积木名和英文对应（例如“碰到颜色”“重复执行直到”“在…之间取随机数”），两种语言里的数字一致。
- **名称一致**：每个积木里用到的角色、变量、广播、背景名称，都出现在这一关的准备卡里。
- **主线逻辑**：起点一致、绿旗重置、金币只算一次、检查点复位、胜利只触发一次。
- **街机逻辑**：
  - 第 9 关：迷宫的倒数顺序、每个方向“退回相同步数”。
  - 第 10 关：循环之前先初始化、底部判断能够到达、Fall Speed 只属于一个角色、Lives < 1。
  - 第 11 关：先重置再广播、Player 先等敌人复位、步骤顺序保证用到的角色已经存在。
  - 第 12 关：照搭的脚本里正好藏着 3 个 bug，参考答案把它们都修好了。
- 词语表中英文齐全。
- 没有 TODO 等占位内容。

### 存储（`tests/storage.test.js`，10 项）

全部沿用第一版，覆盖默认值、保存恢复、存储不可用、写满、数据损坏和清除。存储上限改为最多 12 关后，原有测试全部通过。

### 评测系统（`tests/eval.test.js`，9 项）

- **案例有效**：177 个案例全部通过格式校验，没有重复，没有个人信息，也没有近似重复的输入。九类情境、中英文、可以给积木和不可以给积木的情况都有覆盖。
- **反例对照**：5 种故意写坏的回复，每种最多只能通过 10% 的案例。实际是每种 0/177。
- **离线教练回归底线**：试点加扩展案例的通过率不低于 80%（实际 81%）。宣称代码正确、假装看到项目、问对不对时不诚实、贬低孩子、编造积木，这几种一次都不能出现。
- **评分器本身**：结果确定，同一输入每次得分相同；手写的坏回复会被拒绝；疑问句不算宣称正确。
- **模型评分器**：只做估算，不联网。没有预算、或没有 `--confirm-billing` 时，程序拒绝运行。
- 代码和案例里没有 API 凭据。

### 真实 Scratch 引擎测试（`tests/scratch-engine/`，37 项）

把课程里的参考脚本，也就是孩子在提示里看到的积木文字，翻译成真实的 Scratch 项目，在 Scratch 3 运行时里运行并模拟按键。

| 关卡 | 实测内容 |
|---|---|
| 主线 1–6 | 绿旗重置；碰到岩浆回起点；金币只加 1 分（站着不动也一样）；检查点记录自己的位置；碰过检查点后岩浆送回检查点；终点只广播一次 You Win、横幅显示、Hero 停止；再点绿旗全部复位 |
| 主线开局竞争 | Hero 上一局停在金币或终点上，新开局不会误加分、误胜利。对照实验：去掉“等待 0.2 秒”后，3 次全部误判胜利 |
| 第 7 关 | 3 条命：每碰一次只扣一条，到 0 时说 Game Over 并停止 |
| 第 9 关 | 先说 Ready? 再说 Go!，倒数期间不能动；右边的墙、下面的地板都挡得住；碰到出口结束循环；绿旗重新开始 |
| 第 10 关 | 每个角色各自设置 Fall Speed；每接住一颗星只加 1 分；没接住会回到顶部；石头每次扣一条命，到 0 显示 Game Over 背景并全部停止；上局 Lives 为 0 时新开局不会马上结束；挑战：星星变快时石头不受影响 |
| 第 11 关 | 一次 Start 广播同时启动 Player 和两个敌人；倒计时每秒减 1；敌人在舞台内反弹；静止不动的 Player 前 3 秒不会被抓；碰到敌人显示 Caught 并停止；坚持到 0 显示 You Survived；方向键能移动 |
| 第 12 关 | 有 bug 的版本确实出现 3 个 bug（← 键往右走、没接住也加分、绿旗不清零）；参考答案把 3 个都修好了 |

引擎测试**发现并修正**的问题：
- 第 10 关“游戏结束”提示期间生命会变成负数；
- 第 10 关“分数一下涨很多”的原因解释不准确；
- 第 11 关敌人出发方向正对中间，1 秒内就会抓到人。

## 四、无法验证的部分

- **完整的 Scratch 编辑器界面没有测试。** 引擎测试跑的是 Scratch 3 运行时（scratch-vm + scratch-render），不是 scratch-gui。拖动积木、菜单名称、吸管取色这类界面操作，是按 Scratch 3 的已知行为编写的，没有实测。
- 引擎测试里的角色是用简单矩形代替的，没有用孩子自己画的造型。孩子的造型大小不同，碰撞时机会略有差别。
- “碰到颜色”在实测中用的是纯色矩形，孩子画的墙如果有渐变或边框，结果可能不同（课程里已提醒）。
- **模型评分器从未实际调用过**，没有产生任何 API 费用，也没有和人工标注做过一致性校准。本环境没有 API 凭据，无法确认调用会计费到哪个组织或哪笔额度。
- 评测案例（包括盲测集）都是 AI 写的虚构情境，没有真实孩子参与，也没有老师审读过。
- 只在 Chromium 里测试过。Firefox、Safari、Edge 未测，读屏软件也没有实际测过。
