# 教学质量评测说明

这套评测用来回答一个问题：**当孩子遇到某种情况时，小教练给出的引导好不好？** 它检查课程文字和规则式引导，不检查孩子的 Scratch 项目能不能运行。

## 评测由哪几部分组成

| 部分 | 位置 | 说明 |
|---|---|---|
| 虚构学生案例 | `eval/cases/*.json` | 177 个：试点 37、扩展 120、盲测 20（由另一个代理独立编写）。全部虚构，不含真实儿童资料 |
| 离线教练（被测对象） | `eval/lib/responder-offline.js` | 只用课程内容组合回复：下一级提示、匹配的常见问题、测试提示、诚实说明。不调用 AI |
| 反例回复（对照组） | `eval/lib/responders-control.js` | 故意写坏的回复，用来证明评分器不会“放水” |
| 规则评分器（免费） | `eval/lib/grade-rules.js` | 确定性评分，六个维度 + 失败条件 |
| 模型评分器（可选，付费） | `eval/lib/grade-model.js` | 默认只估算费用，不发请求 |
| 运行入口 | `eval/run.js` | 命令行工具，结果写入 `eval/results/` |

## 案例格式

```json
{
  "id": "P14",
  "phase": "pilot",
  "category": "repeat-trigger",
  "lesson": 4, "step": 2,
  "learningGoal": { "en": "A coin counts only once", "zh": "金币只算一次" },
  "input": { "lang": "en", "text": "my score goes up super fast…", "hintLevelSeen": 1, "attempts": 3 },
  "expected": {
    "behaviors": ["Says to use wait until instead of forever + if", "…"],
    "mustMentionAny": [["wait until", "等待"], ["hide", "隐藏"]],
    "honesty": false, "maxBlocks": 0,
    "problemRef": "The score goes up super fast."
  },
  "failureConditions": ["no-question", "off-topic", "full-answer", "…"],
  "source": "fictional; written by an AI assistant (Claude) …"
}
```

- **category** 九类：看不懂指令、积木顺序错误、脚本放错角色、变量未重置、碰撞或事件反复触发、请求直接给答案、遇到困难、不同程度的提示需求、要求判断代码对不对。
- **mustMentionAny**：每组关键词至少命中一个，回复才算抓住了要点。
- **problemRef**：这一关“常见问题”里正确那一条的英文症状原文。载入时自动换算成序号，课程增删问题也不会错位；找不到就报错。没有写 `problemRef` 的案例默认**不允许**把任何已知问题说成原因（可以用 `"diagnosis": "open"` 放宽）。
- **maxBlocks**：这个情境最多可以出现几行积木。孩子还没看过提示 1、2 时为 0。
- 校验器会拒绝含有姓名、年龄、学校、住址、邮箱、电话等字样的输入。

## 六个评分维度（每项 0–2 分）

| 维度 | 规则评分器怎么判断 |
|---|---|
| Scratch 技术准确性 | 回复里的积木都能翻译成真实的 Scratch 3 积木；关键词组全部命中；没有给出错误的常见问题诊断 |
| 提示是否清晰 | 有具体动作（点、拖、加、测试…）；句子不长；总长度适合孩子 |
| 保留独立思考 | 有提问或让孩子预测、尝试；积木行数不超过上限；没有跳过提示阶梯 |
| 符合年龄 | 没有术语（如“布尔”“迭代”“作用域”）；没有贬低的话（如“这都不会”“显然”） |
| 诚实说明看不到项目 | 孩子问“对不对”时必须说明看不到项目；任何时候都不能假装看过 |
| 不无依据地宣称正确 | 不能说“你的代码是对的”“没问题了”；疑问句不算宣称 |

一个案例**通过**的条件：没有触发任何失败条件，六个维度都至少 1 分；如果案例指定了正确问题，还必须命中全部关键词组。

为了防止固定的模板句子“蹭”到关键词，评分时会排除本次运行中反复出现（至少 15% 的回复）的句子。“遇到困难”和“问对不对”两类除外，因为安慰、诚实说明和自测提示本来就应该用固定说法。“宣称正确”“假装看到项目”“问对不对时不诚实”“贬低孩子”“编造积木”采用零容忍。

## 怎么运行

免费、离线、确定性的规则评测：

```bash
npm run eval
```

只跑某一组案例（`pilot`、`expansion` 或 `holdout`）：

```bash
node eval/run.js --phase holdout
```

### 最近一次结果

| 案例组 | 通过 |
|---|---|
| 试点 37 个 | 35（95%） |
| 扩展 120 个 | 95（79%） |
| 盲测 20 个（独立编写，作者打分前没看过） | 14（70%）；第一次盲测运行时为 17（85%），之后评分器变严格 |
| 全部 177 个 | 144（81%） |
| 5 种反例回复 | 每种 0 |

六个维度里，清晰、独立思考、符合年龄、诚实、不宣称正确都是 100%；失败全部来自“技术准确性”，即孩子换了说法时，离线教练没能对上正确的常见问题。

检查评分器会不会放水（反例回复应当几乎全部不通过）：

```bash
npm run eval:controls
```

结果会写入 `eval/results/`：`offline-<phase>.md` 是给人看的报告，`.json` 含每个案例的回复和分数。

## 可选：模型评分器与费用控制

模型评分只是**筛查**，不能证明 Scratch 项目能运行，也不能替代老师或家长的判断。默认不会发出任何请求。

1. 先估算（不联网，不花钱）：

   ```bash
   npm run eval:estimate
   ```

2. 真要运行时，必须同时满足下面几条，否则程序拒绝启动：
   - 安装可选依赖：`npm --prefix eval/model-grader install`。
   - 环境变量里有 API 凭据（由官方 SDK 读取，程序不会保存或打印它）。
   - 加 `--live`、`--budget-usd <美元上限>` 和 `--confirm-billing`。`--confirm-billing` 表示**你已自己确认**这个凭据计费到哪个组织、哪笔额度，程序无法替你核实。
   - 如果最高估算超过预算的 80%，程序直接拒绝；运行中实际花费到达预算的 80% 会自动停止。

   ```bash
   node eval/run.js --phase pilot --model-judge --live --budget-usd 2 --confirm-billing
   ```

3. 默认模型 `claude-opus-5-5`（可用 `--model` 更换），默认每批 10 个、并发 2（`--batch-size`、`--concurrency`，并发最多 4）。日志只记录案例编号、状态、token 数和估算费用，不记录凭据、请求头或请求正文。

### 价格与估算（截至 2026-10-06 的价格表，使用前请到官网核对）

| 模型 | 输入 $/百万 token | 输出 $/百万 token |
|---|---|---|
| claude-opus-5-5 | 4.00 | 20.00 |
| claude-sonnet-5-5 | 2.00 | 10.00 |
| claude-haiku-5-5 | 0.10 | 0.50 |

估算方法：输入 token 按评分提示词和案例文字的长度粗估（偏高）；输出按每次 600–2500 token 估一个区间，因为这个模型总会先“思考”，思考也按输出计费。全部 177 个案例的估算（未实测）：claude-opus-5-5 约 $2.57–$9.29，claude-sonnet-5-5 约 $1.28–$4.65，claude-haiku-5-5 约 $0.06–$0.23。试点阶段的估算见 `docs/试点报告.md`。

**可能产生额外费用的环节**：只有带 `--live` 的模型评分会花钱。课程本身、规则评测、Scratch 引擎测试、浏览器测试都不花钱。

## 已知局限

- 案例、离线教练和规则评分器最初都由同一个 AI 助手编写，存在“自己出题自己答”的风险。为此加入了：反例对照组、独立的审查步骤（见 `docs/审查记录.md`），以及对失败条件的人工抽查。仍建议老师或家长抽读 10–20 个案例。
- 规则评分器看的是文字模式，能抓住“给完整答案”“宣称正确”“诊断错问题”等，但对“措辞得体但其实没帮助”的回复判断有限。
- 案例是 AI 写的虚构情境，不是真实孩子的话，真实孩子的表达会更多样。盲测集也是 AI 写的，只是和作者独立。
- 离线教练是关键词规则，遇到错别字、近义说法时容易对不上；对不上时会改为诚实说明加“捉虫侦探”步骤，不会乱猜。
- 模型评分器的代码已写好并通过了不联网的测试，但**从未实际调用过**，没有与人工标注做过一致性校准。
