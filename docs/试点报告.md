# 试点报告：两个项目 + 虚拟案例

试点内容：新增第 9 关“迷宫逃脱”、第 10 关“接星星”，以及最初的 30 个虚拟学生案例（审查后增加到 37 个）。目的是在扩展之前，先检查质量和成本。

## 质量

| 检查 | 方法 | 结果 |
|---|---|---|
| 关键积木逻辑能否运行 | 把课程里的参考脚本翻译成真实 Scratch 项目，在 scratch-vm 5.0.300 + scratch-render 2.2.84（无头 Chromium）里运行并模拟按键 | 第 9 关 5 项、第 10 关 6 项全部通过；同时重跑主线第 1–7 关 13 项，全部通过 |
| 课程结构与一致性 | `npm test` 中的内容测试 | 通过：每个项目都有目标、前置知识、准备卡、2–3 步、三级提示、运行检查、常见问题、挑战、反思和家长引导；所有积木都能翻译成真实 Scratch 3 积木 |
| 独立审查 | 另一个审查代理只读审查 | 发现 17 条问题（2 条高严重度），全部核实后处理，见 `docs/审查记录.md` |
| 引导质量（规则评分） | 37 个案例，六个维度 | 离线教练 37/37 通过；技术准确性 99%，其余维度 100% |
| 评分器是否放水 | 5 种故意写坏的回复 | 每种最多通过 1/37 |

引擎实测发现的两个真实问题已经修正：生命在“游戏结束”提示期间会变成负数；“分数一下涨很多”的原因解释不准确。如果只靠文字审查，这两个问题很难被确认。

**需要说明的局限**：37/37 是在审查和修订之后的结果，案例、教练和评分器都出自同一个 AI 助手。修订过程中也确实针对案例调整过回复规则。所以这个数字只能说明“已知情境都有合理引导”，不能代表真实孩子的体验。下一轮扩展会加入新的案例，用来检验这些规则在没见过的情境里是否也成立。

### 无法核实的事项

- 本环境**没有** `ANTHROPIC_API_KEY`，也没有 `ant` 命令行工具，所以无法确认任何 API 调用会走哪个组织、是否绑定你 Max 计划附带的 API 额度。
- 本会话本身的模型调用不会自动使用那笔 API 额度，我也没有用会话的连接做批量调用。
- 因此模型评分器保持“只估算”。要真正运行，需要你：（1）自己确认凭据所属的组织和额度；（2）给出美元上限；（3）带上 `--live --budget-usd <上限> --confirm-billing` 运行。
